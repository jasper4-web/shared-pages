Turf: renditions/rend-timeblock-v4.html (new file — leave v3 intact)

The verdict

"The Line fully built looks good. We just need to make sure the little buttons that you can click

below what's actually going on make sense — for example, if I'm doing the Bible · text Kells,

there should be quick buttons under that that make sense actually towards that, for each

individual thing. But the framework can stay the same."

"I think we have a pretty good framework with The Line and we should move forward with that one —

just making sure that we do it in the best clean way, and we aren't just trying to put it up

quickly and get sloppy results."

The Line ships. Framework locked. This round is about two things: contextual actions per block, and craft.

The problem, precisely

Right now the quick-action row under the live block is generic — the same buttons regardless of what the block actually is. That is wrong. The action under "Bible · text Kells" should not be the same as the action under "Block 1 · SANO" or "Market close."

Every block type needs its own small set of actions that are genuinely the right next thing to do — the thing he would otherwise have to go hunting for.

Design the action set for every block

Read index.html for what exists today (WEEKDAY / SATURDAY arrays, openBlk(), startRun(), logSmoked(), setTrade(), markWait(), markMiss(), tapWin()). Then design and render the action row for each of these:

BlockWhat the actions should actually serve

For each: 2–3 actions maximum. If you need four you have not decided. Say what each does and why it beats the alternative you rejected.

The Bible block deserves particular thought — he named it. It is 3× a week, it is the only social hook in the whole app (Kells is a real person he texts), and it should get the fullscreen locked timer like a work block does. What are the right two buttons under it?

And do it cleanly

"…making sure that we do it in the best clean way, and we aren't just trying to put it up quickly

and get sloppy results."

That is a direct instruction about craft. Concretely:

  • Every touch target ≥44px, and thumb-reachable — he uses this one-handed at 6 AM
  • Consistent spacing scale. No one-off margins
  • Nothing shifts when a block changes state — no layout jump as actions swap
  • Every state of the action row rendered: not started · live · done · missed · waiting · off-script day
  • Actions must be legible at 390px without squinting. This app has shipped 6.5px labels before; do not do that here

Keep from v3

The Line's framework, exactly as built and approved: the rail, deep-work-left, the push strip, the make-up banner, NEXT UP never below the fold, and ALWAYS COUNTS. Do not redesign the region. Do not substitute your X1 fusion — he chose The Line on its own.

Done when

  • The action row designed and rendered for every block type in the table, both weekday and Saturday
  • ≤3 actions each, with a one-line rationale and the alternative you rejected
  • All six action-row states rendered
  • Touch targets, spacing and legibility verifiably clean at 390px
  • Lint clean, no horizontal overflow, screenshotted at 390×844, and you have looked
  • Hand-off: the two action sets you are least sure about, and what would settle them
