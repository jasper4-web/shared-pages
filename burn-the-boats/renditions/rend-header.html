HAND-OFF · FOR THE GM

What to take, and what it costs.

What I produced

data/verses.js — 157 ESV verses across eight themes, with dayFor(dateISO), verseIndexFor(), dayNumber() and rollVerse(p). It attaches to the global scope and also sets module.exports, so the GM can either keep the file or paste the array inline into index.html. Anchored to 2026-07-27 = day 1, which is 1 Corinthians 16:13 on purpose.

renditions/rend-header.html — this page. Six live transitions, the 65/35 open simulator, and a date stepper that proves dayFor() is stable.

Verification, honestly stated

Every verse string was fetched from Bible Gateway's ESV text for that exact reference and then machine-checked to be a character-exact substring of the returned passage. The build fails loudly if any string is not. 40+ entries are excerpts of longer verses — a clean clause lifted verbatim, never a paraphrase, and each is flagged p:1 in the data. I did not use the ESV API (it needs a key); Bible Gateway's own rendering is the source. Small caps for the divine name are flattened to LORD / GOD, which is the standard plain-text convention. As a second, independent check I re-verified a random sample of 14 entries against esv.org itself — a different source from the one used to build — and all 14 matched.

The one thing this costs you

A verse needs more room than two words. The stamp and the verse share one fixed 94px box so the header can never change height and nothing below it can ever jump — but that box is about 44px taller than the stamp alone, which pushes the gauge strip and everything under it down by that much. I judged a permanently taller, calmer plate to be much better than a header that resizes twice a day, but it is a real cost and it is your call, not mine.

The verse type auto-fits (17.5px down to 12.5px) so it always lands inside the box. I trimmed the eight longest verses to verbatim excerpts specifically so nothing has to drop below 15px.

Two traps I hit, so you don't

tsParticles must be initialised. lib/tsparticles/tsparticles.slim.bundle.min.js is the slim package, not a self-starting bundle. Without loadSlim(tsParticles) a container loads happily and reports its particle count, but no shape drawer is registered and not one pixel is ever painted. It fails silently — no console error.

addParticle takes canvas coordinates, not CSS pixels. With detectRetina on, the canvas is devicePixelRatio× the CSS box, so CSS-pixel positions put every ember in the top-left quarter of the plate. Multiply by container.retina.pixelRatio.

Things I found that were not my lane

The furnace's --heat variable I added for direction C is a useful hook regardless of which transition wins: it lets any screen dim or fire the plate without touching the locked styling.

Sunday is a Sabbath screen with no scoring. A verse on the boats plate is the one thing that arguably still belongs there — worth a decision by whoever owns that screen.

The verse pool covers Jul 27 → Dec 30 with zero repeats. If the run extends past Dec 1 as the profile's February–March runway note implies, it will start over from day 1 rather than break.
